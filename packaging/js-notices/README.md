# JavaScript bundle notices

`bundles.json` records the SHA-256 digest of a distributed file and the packages whose code it contains. The report reuses a staged npm notice only for the same name and version. Other notices come from the files in `notices.json`. Several packages distribute identical license texts and share a notice file.

`sources.json` pins each package’s reviewed JavaScript inventory. Each entry covers the relative paths, file digests and sorted component lists, including files reviewed as containing only their owner’s code. The serialization is defined by `inventory_digest` in `scripts/third_party_notices.py`. This lets packaging detect new or changed bundles even when the publisher removes all module paths, comments and source maps.

## Sources for the mappings

- **Pi 1.5.2.** The coding agent’s esbuild metafiles identify inputs with nonzero bytes in each output. To reproduce them, use the dependencies at their paths in Pi’s release lockfile, including development dependencies, and retain the three metafiles from the upstream build script. Match the rebuilt files byte for byte to the npm distribution before using those inputs. Resolve each input to its owning package, including nested installations and workspace members. Inspect generated runtime helpers, the separately copied HTML viewer scripts, and inputs that are themselves bundles. [Build script](https://github.com/earendil-works/pi/blob/v1.5.2/scripts/build-coding-agent-bundle.mjs) · [Build lockfile](https://github.com/earendil-works/pi/blob/v1.5.2/package-lock.json)
- **jiti 2.7.0.** Rspack retains pnpm paths for individually named modules. Concatenated modules also require reviewing the entry points, plugin sources, upstream dependency bundles and lockfile. The loader includes parts of mlly and get-tsconfig. The Babel entry includes adapted import-meta and decorator plugins. The parser and helpers have their own notices. The two aliases in the Rspack configuration resolve to local stubs. [Build configuration](https://github.com/unjs/jiti/blob/v2.7.0/rspack.config.mjs) · [Plugin sources](https://github.com/unjs/jiti/tree/v2.7.0/src/plugins) · [Build lockfile](https://github.com/unjs/jiti/blob/v2.7.0/pnpm-lock.yaml) · [get-tsconfig sources](https://github.com/privatenumber/get-tsconfig/tree/v4.14.0/src)
- **Browser distributions and helpers.** Inspect the source maps in the original npm tarballs before staging strips them. Protobuf.js maps name the individual protobuf utility packages. Web Streams and Google Gen AI contain TypeScript helpers. The qs Browserify module table identifies the side-channel dependencies and intrinsic helpers. Bowser’s polyfilled build includes core-js and regenerator-runtime. Minified loaders, UMD wrappers and compiler helpers have separate records where they contribute code. [Protobuf.js lockfile](https://github.com/protobufjs/protobuf.js/blob/protobufjs-v7.6.6/package-lock.json) · [Web Streams lockfile](https://github.com/MattiasBuelens/web-streams-polyfill/blob/v3.3.3/package-lock.json) · [Gen AI lockfile](https://github.com/googleapis/js-genai/blob/v2.21.0/package-lock.json) · [qs distribution](https://github.com/ljharb/qs/blob/v6.17.1/dist/qs.js) · [Bowser lockfile](https://github.com/bowser-js/bowser/blob/v2.15.0/pnpm-lock.yaml)
- **SDKs and ws.** Anthropic’s parser README identifies the npm package `partial-json-parser`. Its CommonJS and ES module implementations share indgov’s MIT notice. The queue in `ws/lib/limiter.js` identifies Samuel Reed’s async-limiter. Both SDKs identify neoqs in `src/internal/qs/README.md`. Staging keeps the BSD license beside the compiled modules, along with OpenAI’s separately attributed parser and schema-converter licenses in their respective vendor directories. [Anthropic parser license](https://github.com/gov-ind/partial-json-parser/blob/master/LICENSE) · [async-limiter license](https://github.com/STRML/async-limiter/blob/master/LICENSE)
- **Adaptations.** Chalk names its vendored packages in `source/vendor`. Pi identifies the sources of its ANSI handling, input buffering and string width calculations in the corresponding modules. Source comments also identify the upstream code for get-intrinsic’s Lodash path parser, OpenAI’s httpx line decoder, Hono’s middleware composition, Google’s Node debug logger, json-bigint’s two security regexes and Zod’s checksum and schema traversal. The content-type history identifies media-typer 0.3.0. [Lodash 4.17.15](https://github.com/lodash/lodash/blob/4.17.15/LICENSE) · [httpx decoder revision](https://github.com/encode/httpx/blob/920333ea98118e9cf617f246905d7b202510941c/LICENSE.md) · [Jaen’s schema traversal](https://gist.github.com/jaens/7e15ae1984bb338c86eb5e452dee3010)
- **Notice texts.** Versioned package entries use the corresponding npm license, notice or upstream source license. Descriptive entries identify copied code for which the distribution does not give an exact revision. The parameter-decorator and esbuild UMD wrapper releases declare an author and MIT license in their manifests and omit a license file. Their entries include the author, license declaration and MIT permission text. [Parameter decorator manifest](https://github.com/WarnerHooh/babel-plugin-parameter-decorator/blob/master/package.json) · [UMD wrapper manifest](https://github.com/Inqnuam/esbuild-plugin-umd-wrapper/blob/v3.0.0/package.json)

When a dependency changes, review the original build evidence and update the affected component lists and notices before updating the package inventory digest. Generate the report from the pruned runtime for each release target.
